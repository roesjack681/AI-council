# AI Council 0.3.5

0.3.5 修复遗留网页草稿阻塞新问题：在本任务专用页上，先将完整旧稿保存在 IndexedDB，再逐字比对页面未发生变化后移开。已保存的旧请求按完整内容匹配；原记录不存在时，仅将完整历史评审协议封套作为旧格式草稿保存，不凭“AI Council”关键词或单个标记清空。普通内容、引用和追加文字仍保护。备份在设置的“已保留的网页草稿”中查看，恢复只写入原地址的空输入框，不发送。

升级后，仅当前请求所属、因 DRAFT_PRESENT 暂停且没有发送凭据的初始任务可自动重试；普通用户暂停、旧数学任务及结果未知的交付不会自动恢复。运行入口同时拦截没有当前请求归属的旧任务。

0.3.4 改为从聊天入口自动启动网站：配置成员后输入问题，程序会申请首次网站访问权限，建立该任务的专用标签页，检查登录/输入框，必要时自动新建聊天，等待加载后发送。首条消息不再要求已有模型回复样例，也不需要先点“检查能力”；豆包也可从空白专用会话开始。加载或切换新聊天期间会自动复查，并持久化等待状态，默认等待最多 60 秒；会话切换仍使用独立的 30 秒上限。权限未授予时不导航，登录、验证码、无法识别的控件及未知草稿如实暂停。

0.3.3 修复侧边栏尺寸监听与详情弹窗焦点。尺寸观察在组件库初始化前安装，按动画帧合并不同目标的最新测量，取消观察/销毁时清理待处理回调；移除 ResizeObserver 错误拦截。详情使用浏览器原生 dialog，由浏览器管理模态隔离与焦点，支持 Escape、关闭按钮、点击遮罩退出并返回原触发按钮。保留已有聊天、路由和任务逻辑。

0.3.2 修复新旧问题串题与点名聊天：明确以唯一成员名或 @成员名开头的单成员提问直接发送本次原话，不走大脑、不附加讨论 JSON 协议；传输层仍添加唯一跟踪标记。大脑路由出的 direct 任务同样只发送本次原话，直接接收自然语言回复并保存完整原文，不制造结论或共识。

新提问会先持久化暂停旧讨论和未完成的大脑路由，保留全部消息、队列和发送凭据。只有明确恢复指定旧题才继续执行；当前请求归属独立存储，刷新、重启及旧路由回调不会恢复旧题。升级到数据库 v6 时也会暂停此前仍在运行的任务。该版曾保留所有旧草稿；0.3.5 增加了可恢复的旧程序草稿处理，普通草稿仍保留。

0.3.1 保留聊天优先界面、成员头像、大脑路由和单成员点名任务，集中修复恢复、串话、协议纠错和共识判断。大脑请求先落库再分步执行，界面命令不再阻塞等待完整模型回复；确认丢失只读核对，不盲目重发。每题原话锁定，大脑改写仅放入任务背景。

设置中的「新任务的共识要求」可选讨论共识或独立证据。前者保留未核实事实警告，后者要求关键事实独立核验；记录条数不会暗中切换规则。已创建任务保持原设置。点名任务收到目标真实回复即可结束，报告明确未做多成员共识。

首次任务使用独立专用页；只复用已结束任务且交付已完成的专用页，避免暂停任务被下一题占用。大脑也按每题隔离上下文。只复用全文与本请求标记完全匹配的草稿；不会凭「AI Council」关键词清除其他草稿。

长讨论发送当前实体与有限历史窗口，节选会明确标记；所有原文保留在数据库和报告中。原始问题、约束或必需实体本身超限时会如实暂停。

0.2.7 修复未发送会话标签关闭后的安全重建；新增 Gemini 已确认空白首页的首条尝试；富文本按逻辑段落读写并保留空行和缩进，仅完全匹配本请求的遗留草稿可以继续发送。其他草稿仍暂停保护。

0.2.6 根据真实 Chrome Elements 观察补充 DeepSeek 无名称“聊天加号”按钮的定位，仅接受指定页头内唯一匹配的图标；多个匹配或形状改变时保留不支持状态。0.2.5 在个人任务上复核仍因找不到该按钮而暂停，未将测试通过记录为真实恢复。

通过已登录的 AI 网页自动收发消息，组织交叉审查、争议回应与严格共识判断的 Chrome MV3 扩展。不接模型 API，不需要 API Key，不读取密码或 Cookie，不调用私有接口。

本版按用户新要求取消 0.1 的“平台条款状态一律阻断”开关，使用实际网页 DOM 检查决定是否能够尝试自动运行。规则信息仍可查看；页面就绪不等于官方授权，也不等于该账号已完成全流程验收。

## 升级到 0.3.5

1. 打开 `chrome://extensions`，找到 AI Council，点击“重新加载”。加载目录仍是 `D:\Project\AI-council\dist`，无需删除扩展或清空数据。
2. 关闭旧侧边栏，再点击扩展图标打开；页脚应显示 **0.3.5**。主界面改为聊天页，右上角进入「设置」。
3. 在设置中确认隐私提示，添加模型名称和平台。首次添加或发送时 Chrome 会请求网站访问权限；已授予的权限由浏览器保留。
4. 回到聊天页直接发送问题，例如“光头强在吗”。程序会自动建立专用会话、检查与准备页面并发送；不要求手动打开网站、发测试消息或逐次检测。
5. 如网站需要登录、验证码或 Chrome 拒绝访问，按具体提示处理；记录会保留。旧题只有明确选中并恢复才继续，新问题不会恢复旧题。

系统为每个任务和参与者建立独立标签页，自动输入、发送、确认网页消息、等待完整回答、交接给其他参与者，并根据共识规则结束和生成报告。发送时可能短暂切换活动标签页以操作富文本编辑器，提交后恢复原标签页；切换新对话时保留专用页在前台，避免后台页面延迟渲染，不需要人工逐条发送或搬运回复。

0.2.5 修正 `SESSION_NOT_EMPTY` 的会话准备：新对话按钮支持 aria-label、title、aria-labelledby；点击前保存准备记录，跨调度周期等待最多 30 秒，不反复点击，也不消耗发送重试。清空本任务专用页面后，保留该页面切换前的读取证据用于首轮尝试，不要求再打开一个旧回答标签。读取能力仍待首条真实回复验证。任务里可展开“专用会话准备诊断”，查看平台、标签、准备阶段与具体原因；缺少按钮或超时会保留实际原因并暂停。

0.2.4 修正发送后的恢复：模型生成时继续只读轮询；确认丢失时最多核对五次原请求标记，确认后继续等待，仍未知才暂停，不直接重发。标记跨多个 DOM 节点也可核对；成功交付会清除当前错误，历史失败保留在审计日志。队列显示参与者名称和核对次数。已暂停的旧任务不必重建。

0.2.3 针对 ChatGPT 的 `OUTPUT_NOT_FOUND` 增加了回复定位：支持无旧版属性的发言标题、没有独立消息外层的布局、`display: contents` 容器及可访问性标题；优先读取可见标题文本并忽略零宽分隔。按下一条发言、回复操作栏或输入区界定回复范围，防止把整段对话当成回答。旧任务仍可重新检查并恢复，保留原始记录。页面诊断增加不含正文的结构版本、标题数量与标签信息。

**当前验证边界：** 生产 DOM 执行器和完整讨论链路已在受控网页中测试；没有把测试页面回复冒充真实模型。真实账号的完整讨论与大脑路由尚未验收；此前已接收 DeepSeek、Gemini、ChatGPT 的真实首轮回复，并复现第 1 轮本地事务失败。只读检查见到 DeepSeek、Gemini 和 ChatGPT 的对话控件；用户提供的 0.2.1 ChatGPT 诊断确认输入框和完成控件可匹配，但回复数为 0。本次修复通过十个布局回归测试，仍需在当前真实页面重新检查。豆包此前打开页面显示需要登录。各平台页面变化可能使检测不匹配，必须如实暂停。

## 首次安装

解压 `release/ai-council-0.3.5.zip`，在 Chrome 扩展管理页启用“开发者模式”，选择“加载已解压的扩展程序”，选择解压后的目录。也可直接选择已构建的本项目 `dist` 目录。点击扩展图标打开侧边栏。

此前下载的 ZIP 不会自动更新，请使用 0.3.5 包或当前 dist。

无需安装 Node 就能加载现有构建产物。源码开发需要 Node.js 22.12+ 和 npm：

```powershell
cd D:\Project\AI-council
npm ci
npm run build
```

## 运行与测试

```powershell
npm run dev
npm run build
npm run test:coverage
npx playwright install chromium
npm run check:compliance
npm run test:e2e
npm run verify
npm run package
```

开发预览地址为终端地址下的 `/sidepanel.html`。预览使用独立数据库，没有 Chrome 网页执行能力。修改源码后构建并重新加载扩展。

`verify` 顺序执行严格构建、单元覆盖率、权限/API 边界检查和浏览器测试；首次运行前需安装 Playwright Chromium。`package` 生成扩展 ZIP、源码 ZIP 和 SHA-256 文件。测试浏览器与个人浏览器隔离，测试响应只位于 tests，不打入扩展。

## 网页运行条件和异常

Chrome、电脑、网络及账号会话需要保持可用。侧边栏打开时每约 3 秒驱动一次短调度，关闭侧边栏后由每 30 秒 alarm 调度，模型响应和消息交接可能有相应延迟。MV3 状态均持久化，不要求 worker 常驻。

网页加载或切换期间暂缺输入框会先自动等待复查。超过准备期限、未登录、验证码/访问阻断、发送结果长期未知、会话被切换、标签页关闭、回复结构改变、超时或协议连续修复仍失败时，明确暂停并保存记录。不会绕过验证，也不会重复发送结果未知的请求。若平台需要真实硬件输入而不接受 DOM 事件，该平台不能据当前实现声称可用。

如新标签页恢复了旧对话，系统尝试点击明确的新对话按钮；不能确认空白会话时不发送，避免污染原讨论。不会覆盖未发送草稿。讨论专用标签页关闭后不会盲目开新页面重发。
